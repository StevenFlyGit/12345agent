# 后端能力缺口清单（前端改造配套）

> 来源：2026-08-28 前端按 `design-proposals/prototype-A-linear-pipeline.html`（A 版）改造时识别。
> 现状：以下能力后端暂不支持，前端已采用**状态推导 / 占位展示 / TODO 标注**方式兼容，**不影响现有功能与业务流程**。
> 约定：优先级 P0 = 影响业务正确性，建议尽快补；P1 = 显著提升体验，建议排期；P2 = 锦上添花。

| 编号 | 字段 / 数据名称 | 所属业务场景 | 用途说明 | 建议优先级 | 前端当前兼容方式 |
|------|----------------|--------------|----------|-----------|------------------|
| **G-01** | 节点完成时间戳（`completed_at`，每阶段一个） | Pipeline 轨道节点 / 流转时间线 | 展示"录入 10:32 完成""理解耗时 40s"等，让流水线的"流转感"有据可依；也是后续统计各环节耗时的基础 | **P1** | 仅显示"已完成/进行中"状态文案，不显示时间；状态由 `understanding/work_order/...` 字段是否为 null 推导 |
| **G-02** | 更新诉求理解结果的接口（如 `PUT /api/cases/{id}/understanding`） | ② 诉求理解面板 | 工作人员在该面板可直接编辑时间/地点/事件等要素，但**编辑结果仅存于前端内存**，刷新或换机即丢失，且后续工单生成仍基于后端原始值。需要回写接口保证人工修正生效 | **P0** | 组件内已标注 `TODO(backend-gap)`；底部提示"修改内容仅在当前会话生效"。业务上建议后端在生成工单时以最新人工修正值为准 |
| **G-03** | 更新预回复的接口（如 `PUT /api/cases/{id}/reply` 或将编辑后的 pre_reply 随 confirm 提交） | ⑤ 回复辅助面板 → ⑥ 审核确认 | 预回复明确设计为"可编辑"，但编辑内容不回写，确认环节预览的仍是后端原文，人工润色成果无法落库，影响"AI 生成 → 人工润色 → 提交"的核心闭环 | **P0** | 组件内已标注 `TODO(backend-gap)`；底部提示"编辑仅在当前会话生效" |
| **G-04** | 扩展 `audit_log` 条目为结构化流转事件（建议字段：`step`、`actor`、`actor_role`、`duration_ms`、`payload_digest`；并在 workorder/classify/reply 各阶段完成时自动追加事件） | 流转时间线（B 版原型侧栏）/ 操作审计 | 现有 `audit_log` 仅在**创建**与**确认**两个时机写入，中间三个阶段无任何事件，无法支撑时间线视图与过程审计；`actor_role`（system/ai-engine/staff）用于区分是引擎动作还是人工动作 | **P1** | 前端未渲染时间线组件（属 B 版方案，本次未落地）；确认面板的 audit_log 列表正常展示现有字段 |
| **G-05** | 引擎调用失败 / 重试事件（`action: "error" | "retried"`） | 全局忙碌态 / 异常提示 | 引擎调用失败时目前只有前端 alert 提示，无任何留痕；记录失败事件便于排查引擎稳定性问题 | **P2** | 前端 `runStage` 的异常仅静默放行（`finally` 复位 busy），未做留痕；等待后端事件结构确定后补充 |
| **G-06** | 节点级"需注意"标记的结构化来源（当前已部分具备） | Pipeline 轨道 attention 态 | 轨道的琥珀色"需补充"态目前由 `understanding.needs_clarification`、`classification.needs_manual` 推导，**已可用、无需新增**；若后续其他节点（录入/工单/回复/确认）也需要异常态，需对应布尔标记 | **P2** | 已实现：理解节点缺字段、分类节点需人工复核时，轨道节点自动切换为琥珀色警示态 |

## 补充说明

1. **G-02 / G-03 是同一类问题**：AI 产出物的"人工编辑 → 回写"通道缺失。建议统一设计为 `PUT /api/cases/{id}/{stage}`（stage ∈ understanding / reply），或在 confirm 接口中接受可选的修正载荷。
2. **G-01 / G-04 可合并实现**：后端在各阶段完成时向 `audit_log` 追加结构化事件（含 `at` 时间戳），节点时间戳即自然可得，无需单独字段。
3. 本清单不涉及任何前端阻断项——以上全部缺口前端均已兼容，后端补齐后前端只需移除对应 TODO 并接入真实数据。
